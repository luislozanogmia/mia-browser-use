# Local extension reloads

Unpacked installs offer **Settings → Reload local edits when idle**. It is off by default, and never available in packaged/store installs. After installing this source change, reload once through Chrome's Extensions page, enable the setting yourself, then close Settings and Run/Edit and leave the chat draft empty. No script or external process controls Chrome's extension management.

The extension reads a fixed allowlist of its own bundled files every five seconds using SHA-256 and `cache: no-store`. It waits at least ten seconds after the last detected change. It can reload only while the authenticated bridge is connected, no browser command is executing, the bridge's fresh aggregate says every task/future has finished, and every connected side panel has recently reported an empty composer and no open Settings, Run/Edit, or room-name edit. Before reload, every panel must acknowledge a new random nonce and temporarily make its body inert, preventing typing or submission between the clean check and reload. Dirty panels reject the request. New panels, disconnects, new browser commands, busy task snapshots, missing acknowledgements, or timeout abort the handshake and restore controls and focus. The background rechecks idle after all acknowledgements. Unknown, stale, disconnected, or failed reads hold the reload. Close panels hold it too. Production installs never enable it. It neither fetches executable remote code nor calls eval. The ordinary extension-owned `chrome.runtime.reload()` is the only reload API.

The watcher handles extension source files only, not Python backend changes. Manifest permission changes may still require Chrome's own confirmation. A suspended/restarted service worker takes a new baseline, so changes made while it was asleep might require one manual reload. Actual unpacked Chrome verified two opt-in reloads from a temporary CSS comment and its removal. Settings held the first reload; an unsent draft held the second for 30 seconds. Closing Settings or clearing the draft released the corresponding reload, and the bridge disconnected/reconnected without a manual reload. Chrome closes the side panel during extension reload; reopening with Alt+Shift+M restored the saved chat. The setting is enabled in this development profile. The unit tests use stub APIs; they do not prove worker-sleep behavior or backend scheduling races. Those limitations remain unverified.

Run its focused tests with `node --test tests/js/dev_reload.test.cjs` from the repository root.
